> **v1.1 更新**：已核实两个本地安装（ComfyUI Desktop + SD-WebUI），方案从"全新安装"简化为"直接配置对接"。

**改动 2**：`_cp_to_input()` 删掉 sshpass SSH，改用本地上传 API（第 206-218 行）：

```python
async def _cp_to_input(self, filename: str):
    """本地模式：把 output/ 的文件通过 ComfyUI /upload/image API 传到 input/"""
    from pathlib import Path
    src = Path("storage/output") / filename
    if not src.exists():
        src = Path("storage/images") / filename
    if src.exists():
        result = await self.client.upload_image(str(src), subfolder="")
        logger.info(f"[Video] 已上传到本地 ComfyUI: {result.get('name')}")
```

### 4.3 新增 LTX-Video Provider（Phase C）

3. `agents/video_agent.py` 中把 HunyuanVideo 引用换成 LTXVideo

## 五、性能预期与资源规划

### 5.1 速度预期（M4 24GB，比 RTX 3090 慢 3~8 倍）

| 任务 | AutoDL 3090 | **M4（预估）** |
|:---|:---:|:---:|
| SD1.5 出图 512×512（20步） | ~2秒 | **~15-30秒** |
| SD1.5 出图 1024×1024 | ~4秒 | **~40-90秒** |
| LTX-Video 480p 5秒 | ~30秒 | **~10-30分钟** |

> 单集漫剧（20 分镜）本地出图约 **5-15 分钟**，可接受；视频是瓶颈，先跑 1-2 个分镜验证。

### 5.2 内存策略

- 24GB 统一内存：SD1.5 无压力；跑 LTX-Video 时关掉浏览器等大程序
- 两个工具**不要同时出图**（MPS 资源会互相争抢）
- 内存不足时 ComfyUI 启动加 `--lowvram`

## 附录 D：Ollama 模型国内加速下载（已实测）

`ollama pull` 在部分网络下只有几 KB/s。实测可用 **ModelScope（阿里源）** 快速下载 GGUF 再注册给 Ollama：

```bash
# 1. 从 ModelScope 下载 qwen3:8b 的 GGUF（约 4.7GB，5MB/s+）
curl -L -C - -o /tmp/qwen3-8b-q4_k_m.gguf \
  "https://modelscope.cn/models/Qwen/Qwen3-8B-GGUF/resolve/master/Qwen3-8B-Q4_K_M.gguf"

# 2. 写 Modelfile 注册到 Ollama
cat > /tmp/Modelfile <<'EOF'
FROM /tmp/qwen3-8b-q4_k_m.gguf
EOF
ollama create qwen3:8b -f /tmp/Modelfile

# 3. 验证
ollama list   # 应出现 qwen3:8b
```

> 其他量化档：`Qwen3-8B-Q5_K_M.gguf`（5.4GB，质量略好）/ `Qwen3-8B-Q6_K.gguf`（6.3GB）。

目标：最终出片不能太像 AI 生成。四个方案全链路落地并验证。

## 附录 L：FLUX GGUF + VoxCPM2 落地记录（2026-08-27）

> 把推荐清单里「本机跑不了」的 FLUX.1 与「仅下载未接入」的 VoxCPM2 真正落地闭环。核心：用 **GGUF 量化**绕开 M4 无 CUDA + MPS 不支持 fp8 的坑。

### L.1 背景：为什么 FLUX fp8 跑不起来（根因确认）

- 直接加载 `t5xxl_fp8/FLUX fp8` 权重时报错：
  `TypeError: Trying to convert Float8_e4m3fn to the MPS backend but it does not have support for that dtype.`
- **根因**：ComfyUI 及 MPS 后端对 `Float8_e4m3fn`（fp8）dtype 无原生支持，整图 fp8 权重无法在 M4 上执行。
- **解法**：改用 **ComfyUI-GGUF** 节点，加载 GGUF 量化模型，**按层按需反量化到 fp16**（纯 torch 运算，`GGMLLayer.cast_bias_weight()`），MPS 完全兼容。

### L.2 FLUX.1-schnell GGUF 方案

**模型仓库**：`city96/FLUX.1-schnell-gguf`（原 `Comfy-Org` 仓库对 HF 下载返回 HTTP 401，须换用此仓库）。

**下载文件（已就绪）**：

| 文件 | 大小 | 位置 |
|:---|:---:|:---|
| `flux1-schnell-Q5_K_S.gguf` | 8,263,222,304 字节（8.26G） | ComfyUI `models/diffusion_models/` |
| `clip_l.safetensors` | 246M | ComfyUI-Shared `text_encoders/` |
| `t5xxl_fp8_e4m3fn.safetensors` | 4.9G | ComfyUI-Shared `text_encoders/` |
| `ae.safetensors` | — | ComfyUI 本地可识别 |

> **下载稳定性**：HuggingFace 走 HTTP/2 时对连接流报 `CANCEL (err 8)` 导致下载中断（停在 4.7G）。改用 `curl --http1.1 -L -C - --retry 10 --retry-delay 5` 续传后成功。

### L.3 代码改动（`providers/comfyui/client.py`，2 处）

**改动 1**：`build_flux_txt2img_workflow()` 切换为 GGUF 加载器 `UnetLoaderGGUFAdvanced`（替代原 fp8 UNETLoader）：

```python
    "inputs": {
        "unet_name": unet_name,          # 默认 "flux1-schnell-Q5_K_S.gguf"

        "patch_on_device": False,

},
```

**改动 2**：修复 `wait_for_completion()` 不检查实际执行结果的 bug——原先仅凭「不在运行/等待列表」就判成功，现改为读取 history 的 `status`：

```python
if prompt_id not in running_ids and prompt_id not in pending_ids:
    history = await self.get_history(prompt_id)
    info = history.get(prompt_id, {})
    outputs = info.get("outputs", {})
    status = info.get("status", {})
    if not status.get("completed", False):
        err_msg = "unknown error"
        for mt, md in status.get("messages", []):
            if mt == "execution_error":
                err_msg = md.get("exception_message", err_msg)
        return {"success": False, "prompt_id": prompt_id, "error": err_msg, "outputs": outputs}
    return {"success": True, "prompt_id": prompt_id, "outputs": outputs}
```

> 该默认值经 `comfyui_provider.py` 的 `build_flux_txt2img_workflow()`（`model_type == "flux"` 分支）读取生效，改 client.py 默认即接入正式管线。

### L.4 VoxCPM2 接入 TTS

- **包**：`pip install voxcpm`（API 版本 2.0.3）。
- **模型**：`models/voxcpm/VoxCPM2/`（audiovae.pth 359M + model.safetensors 4.3G + tokenizer）。
- **接入点**：`providers/audio_tools.py` 的 `_get_vox()`（`from voxcpm.core import VoxCPM`）、`_synthesize_vox()`（`model.generate(text=…, cfg_value=2.0, inference_timesteps=10, normalize=True)`）。
- **配置**：`config/config.yaml` → `tts.engine: "voxcpm"`。
- 模型在 M4 上自动从 bfloat16 调整为 **float32** 运行，24GB 统一内存足够。

> 注意：`pip install voxcpm` 会把 venv 内 torch 从旧版升到 2.13.0。已验证不影响 ComfyUI HTTP 链路与 piper/voxcpm 使用。
